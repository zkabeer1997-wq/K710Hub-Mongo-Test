# Language switching (runtime UI translation)

K710 Hub does **not** use `next-intl` or per-locale message files. The repo already ships a runtime UI translation system, and it is reused as is:

- `components/i18n/LanguageProvider.jsx` (mounted in `app/layout.js`): the chooser dialog, the saved choice (`localStorage` `k710-language-v1`), a DOM walker + `MutationObserver` that translates text nodes and `placeholder` / `title` / `aria-label` attributes, a per-language cache (`k710-ui-translations-v4:`), RTL/`lang` handling.
- Engines: Chrome's on-device `Translator` API when available, otherwise `POST /api/translate-ui` (same-origin only, rate limited) which calls LibreTranslate mirrors (MyMemory as a Tagalog fallback).
- `public/ui-strings.json`: the **allow-list manifest**. Only text whose whole text-node equals a manifest string is translated, and the API refuses anything else. Player-entered text is never sent.
- `scripts/extract-ui-strings.js`: regenerates the manifest from `app/`, `components/`, `lib/` (`.js .jsx .mjs .ts .tsx .css`). It runs in `npm run dev` and `npm run build`; commit the regenerated file when you add UI copy.
- `lib/i18nLanguages.mjs`: language list, code resolution, `languageShortCode()`, `QUICK_LANGUAGES` (moved out of the provider, behaviour unchanged).

## Header switcher

`components/i18n/LanguageSwitcher.jsx` renders in `SiteHeader`: a real `<button>` showing the current code (`EN`, `ES`, `ZH-HANT`...), `aria-haspopup="dialog"`, accessible name "Language: {name}. Change language", 44px tall. On desktop it sits beside the UTC clock; at <760px the header button is hidden and the mobile menu starts with a full-width row (`EN English`) that closes the menu and opens the chooser.

It opens the provider's chooser (`role="dialog"`, `aria-modal`): focus moves into the dialog, quick-pick chips (English, Spanish, French, German, Portuguese, Turkish, Arabic, Korean, Chinese) or a typed/searchable language, **Escape** or Cancel closes it (only after a language has been chosen once) and focus returns to the switcher. The floating globe button stays only on pages without the header (`/gate`) and is hidden via CSS when the header switcher exists.

**Forge intro interplay is unchanged**: on a first visit the chooser opens as before and `HomeForgeIntro` / `GateExperience` wait for `hasChosenLanguage` from `useLanguage()` (the context only gained `languageCode` and `translationStatus`). Admin pages skip the chooser.

## Game terms stay in English

`lib/i18nTerms.mjs` holds `PROTECTED_TERMS` (KvK, TG, TTG, Noble Advisor, Chief Minister, Governor Gear, Flamedragon Tyrant, Swordland Showdown, ...). Before translation each term is replaced by a placeholder (`[[0]]`), and put back afterwards, both for the on-device translator (in the provider) and for the server route (`/api/translate-ui`). Matching is whole-word and longest-first (`TG` never matches inside `TGIF`). If an engine damages a placeholder, that string stays in English rather than risk a wrong term. For markup you control, `translate="no"`, `class="notranslate"` or `data-k710-no-translate` also exclude an element.

**Admin-provided translations**: `ADMIN_TERM_TRANSLATIONS` in the same file maps a language code to `{ "English term": "translation" }`; a listed term is substituted for that language instead of staying English. It is a code-level list today (no admin UI yet). Not verified against the real engines in this sandbox (no network): the placeholder round-trip is unit-tested with fake engines only.

## Coverage and limits

- Static copy in JSX text, string literals and template literals without `${}` is picked up automatically, including `lib/*.mjs` (this phase added `.mjs` to the extractor: before, strings such as the form window messages, vote labels and status labels in `lib/*.mjs` were not translatable). `tests/i18nCoverage.test.mjs` fails if the member form / dashboard / appointment strings drop out of the manifest.
- Strings assembled at runtime (`Day 1 Construction: Pending`, "3 of 3 selected", countdowns, dates) are **not** translated as a whole; their static pieces may be. Prefer separate text nodes for static labels.
- Admin-authored content (guides, blurbs) is not in the manifest and stays as written.
- Translation quality depends on the engine; the first translated page load needs network.
