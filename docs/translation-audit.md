# Translation audit

Date: 2026-10-09. Branch `feat/translation-full` (from `feat/member-dashboard`).

## 1. How the OLD system worked (main, before the catalog rewrite)

Found with `git log --stat -- components/i18n lib/i18nTerms.mjs public/ui-strings.json app/api/translate-ui`.

- `components/i18n/LanguageProvider.jsx` walked the **whole DOM** in the browser: every text node plus
  `placeholder`/`title`/`aria-label`/`alt`, skipping `script/style/code/pre`, `.notranslate`,
  `translate="no"` and `[data-k710-no-translate]`; a MutationObserver translated later changes; the
  originals were restored when switching back to English. Results cached in localStorage (`k710-ui-translations-v4:<lang>`).
- Translation engine, in order: Chrome's on-device `Translator` API (Chrome only, needs a language-pack download and a user gesture), else `POST /api/translate-ui`.
- `/api/translate-ui` proxied public LibreTranslate mirrors, but **only for strings on an allow-list**,
  `public/ui-strings.json` (generated by `scripts/extract-ui-strings.js`): **9,383 strings, about 3,950
  real sentences/labels** (the rest are ids, CSS vars, keys). Max 64 strings/request, 320 characters/string, rate limited.
- Game terms were protected by `lib/i18nTerms.mjs` (mask before, restore after).
- Languages: ~40 (anything Chrome or LibreTranslate offered).
- Coverage: every page that used static strings was covered *if* the string was in the allow-list.
  Weaknesses: unlisted/dynamic text (DB content, admin-written text, API errors) was not translated;
  free mirrors were unreliable; Safari/Firefox/phones without the Chrome API depended on those mirrors.

The catalog rewrite removed the DOM walker and the endpoint, replaced them with `t()` over 106 keys
and nine **empty** locale files, so non-English choices only changed `dir`. That is the regression.

## 2. Where text reaches users (inventory)

Heuristic counts on the branch (JSX text nodes between tags, quoted `placeholder/title/aria-label/alt`
attributes, and string literals that look like sentences). Counts are approximate (regex based) but
consistent between areas.

| Area | Files | JSX text | attributes | sentence-like string literals |
| --- | ---: | ---: | ---: | ---: |
| Member pages + forms (`app/dashboard, forms, power-profile, flamedragon, prep-phase-backpack, login, gate`, `components/member`) | 50 | 247 | 14 | 222 |
| Public pages (`app/guides, events, alliances, gallery, about, timeline, help, glossary, interest`, home) | 37 | 234 | 38 | 273 |
| Tools / calculators UI | 47 | 560 | 51 | 490 |
| Shared components (header, footer, notices, ui) | 66 | 139 | 28 | 167 |
| `lib/*` data text (guides, tool/game data, home copy, glossary, form field text) | 213 | n/a | n/a | 1,642 |
| Admin + API routes (OUT of scope) | 192 | 717 | 170 | 1,400 |

Other sources, all reaching users and all covered by the runtime layer rather than the catalog:

- DB-driven content: guide builder pages, announcements/notes, alliance blurbs, gallery captions, page text overrides (`page_text`), event text, hero catalog names.
- API error/success messages shown by forms (English strings in `app/api/**`), toasts.
- Document titles and `<meta>` (server HTML stays English; the overlay translates `document.title` after load).
- Dates and numbers: components use `Intl` with the active language (dashboard) or the browser default; the overlay does not touch numbers/dates.
- Emails/alerts: none are sent to members from this app (Discord/Drive exports are admin tools, out of scope).

## 3. Result after this work

- Catalog keys: 136 (was 106) in `i18n/en.json`, with translator notes. Locale files stay empty stubs in git until the owner runs `npm run translate` with a working key.
- Hard-coded in the catalog sense (not yet extracted): roughly 1,150 JSX strings in member/public/tools/shared components plus the `lib` data text. They are translated at runtime by layer B.
- Crawl coverage with the mock engine: see `docs/translation.md` and the final report (per language, per page).
